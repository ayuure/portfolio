DevOps Africa · 2025 – present

AI-powered regression impact analysis

Problem
When code changed, QA could not easily see which other parts of a connected system it might affect, or whether the change had reached the QA environment yet.
What I did
  • I designed and built a tool, powered by Claude, that analyses source-code changes and flags regression risks across connected system components.
  • I connected it to GitHub and Jira so it links tickets, code changes and system dependencies. This shows the potential blast radius of each change.
  • I used GitHub Actions data to confirm which changes had been deployed to the QA environment.
  • I made it read-only, so it can never change code, tickets or deployments.
Jira tickets GitHub code changes GitHub Actions deployments
→ Claude analysis → Regression risk report for QA
Result
The team can see the regression risk of each change more clearly, which helps us focus testing on the areas most likely to break.

AmaliTech · for a major European telecom provider · 2022 – 2025

Automation and quality testing across two telecom platforms

Problem
The client needed two products tested. Its employee onboarding product had an admin web portal, a Flutter web app and a mobile app, and the admin portal had no automation framework. Its global careers website was used across many regions, so it had to work on every browser and device and meet corporate and EU compliance standards.
What I did

Onboarding app: admin portal, Flutter web and mobile app

  • I designed and built a Selenide and TestNG framework in Java from scratch, and I used it to automate the key user journeys and interface behaviour of the admin portal.
  • I automated REST API tests with RestAssured for the endpoints behind the onboarding flows.
  • I tested the iOS and Android onboarding flows manually to make sure new hires had a smooth experience.
  • I checked that the Flutter web and mobile apps met the functional requirements on every platform.
  • I used GitHub Copilot to write test scaffolding and assertion boilerplate faster.

Global careers website

  • I tested the site across regions, browsers and devices.
  • I ran accessibility and performance audits with Google Lighthouse, helping the team meet corporate and EU compliance standards.
  • I ran cross-browser and mobile compatibility testing on LambdaTest.
  • I built and maintained visual regression tests to catch UI inconsistencies before deployment.
  • I used ChatGPT to generate and review complex edge-case test scenarios, widening test coverage.
Result
The onboarding product's key journeys and APIs were covered by automated tests that could be re-run on every release, which left manual testing time for the mobile apps. The careers website was audited for accessibility and performance and checked across browsers and devices, and visual regression tests caught UI issues before they reached users.

DevOps Africa · for PurpleWave Auction · 2025 – present

End-to-end, API and database testing for an inventory system

Problem
PurpleWave's inventory system manages auction listings in a shared monorepo and is released to production every week. A defect in a listing could come from the UI, the API or the database, so every layer needed testing.
What I did
  • I write and maintain Playwright end-to-end tests for the listing workflows, adding coverage without breaking a shared codebase.
  • I test REST APIs with Postman, checking request and response structures, status codes and error handling.
  • I query the MySQL database to confirm that listing data is stored and updated correctly after UI and API actions.
  • I run SQL injection tests on input fields and API parameters to confirm that attackers cannot read extra data or change records.
  • I use the Network tab in Chrome DevTools to find out whether a defect is in the frontend or the backend before I report it.
Result
Every feature is integration-tested and validated before its weekly production release. My defect reports name the layer at fault, so developers know where to start.
